# 元作品：MeetForMe のアプローチ

- リポジトリ: https://github.com/TAK0-wasa/ShipLab-Hackathon-2026
- Web: https://meetforme.vercel.app/
- チーム: RememBug Me（3人） / テーマ「かゆいところに手が届くアプリ」

## 概要

メンバー1人に1体の AI 代理人を付け、代理人どうしが会議して推薦案を出す。

1. 考えを預ける（約2分）：代理人に案と本音を話す。質問は4つほど
2. 代理人どうしが会議：全員が預けると自動開始、推薦案が出る
3. 承認して決定：全員承認で決定

## 工夫

- 採点は案の作者を伏せる / 2回採点して平均 / 1位が入れ替わったら聞き直し
- 合計点・順位は AI ではなくルールで計算
- 決定後に本音を共有ストアから削除
- 進行役 AI が合体案・新案を出す

## 構成

- フレームワークなしの HTML/CSS/JS、Electron（Windows）+ Vercel
- Supabase（Postgres 1テーブル + RLS、Edge Function で Claude を中継）

## 気になる点（別アプローチの手がかり）

- 「AI 同士の会議」は見ていて面白いが、本当に必要？ 本人の入力を直接集計するのと何が違う？
- 代表者がページを開いている間しか会議が進まない（同期性が残っている）
- 代理人が本人の意図を正しく代弁している保証がない → 納得感の源泉が「AIが言ったから」になりうる
- 4問の聞き取りで本音が取れるか
- 合意のゴールが「全員承認」だけ。反対者が出たときのループは？
