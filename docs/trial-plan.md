# 試してもらう計画

課金を考える前に、実際のイベントで使ってもらい、使われ方と困りごとを集める。

## 誰に頼むか

| 相手                               | 場面                                 | ねらい                                       |
| ---------------------------------- | ------------------------------------ | -------------------------------------------- |
| GDGoC KIT                          | 勉強会のテーマ決め、イベント企画     | 運営側の使い勝手（法人・団体プランの必要性） |
| 身近なハッカソンの運営・参加チーム | チームのテーマ決め（1チーム5人まで） | 本来の用途での使い勝手                       |
| CirKit などのサークル・ゼミ        | 企画やテーマの決定                   | ハッカソン以外への広がり                     |

## 確かめたいこと

- 招待されてから、案を出して承認するまでに迷うところはないか
- ○△✕ の判定に違和感はないか（AI の判定に納得できるか）
- 締切までに決まったか。決まらなかったら、どこで止まったか
- 1チーム5人・12人の上限で足りたか
- 運営が複数チームで使うとき、何が足りないか（一括作成・管理画面・権限の譲渡）
- 払うとしたら、何にいくらまでなら払うか

## 数えること

Convex のデータから集計できる範囲で、まず手作業で数える（集計の仕組みは必要になってから作る）。

- 作られた会議の数と、1会議あたりの人数・案の数
- 決定まで進んだ割合と、決まり方（承認・最多票・ルーレット・ホスト）
- やり直し（2回目）になった割合
- AI が止まって手動判定になった回数
- 上限（1日の会議数・人数・案の数）に当たった回数

## 聞き方

- 使ってもらったあとに、短いアンケート（5問程度）と、可能なら10分ほどの聞き取り
- 運営側には「一括作成・管理画面があったら使うか」「いくらなら払うか」を直接聞く

## 進め方

1. 身内（GDGoC KIT・CirKit）で数回試す
2. 迷いやすいところを直す
3. 外部のハッカソン運営に、1イベントで試してもらう
4. 結果をもとに、法人・団体プランを作るかを決める
