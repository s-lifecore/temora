# 決定ログ

| 日付 | 決めたこと | 理由 |
|---|---|---|
| 2026-11-20 | プロジェクト用ディレクトリと docs/ を作成 | メモから始める |
| 2026-11-20 | 承認ルール：メンバー5人未満は全員承認、5人以上は3分の2以上の承認で決定 | 全員一致だと1人の未反応・反対で止まる（MeetForMe の弱点）。少人数では全員の納得を優先 |
| 2026-11-20 | 各案を判断軸ごとに ○△✕ で照合して見せ、それを見て承認するか判断する | AI に結論を出させるのではなく、判断材料を見える形で並べる |
| 2026-11-20 | AI は各案に判断軸ごとの ○△✕ を付けるまで。候補はルールで最大3案に絞る（譲れない軸で✕の案を除外 → ○の数順）。案が3つ以下なら全部出す | 元祖は AI が1案に絞り人間は追認するだけ。こちらは AI は材料をそろえ、選ぶのは人間 |
| 2026-11-20 | 各自が3案のうち「これならいい」案にいくつでも承認を付ける（承認投票）。承認ルールを満たした案を採用し、複数あれば承認数が最多の案 | 単一選択だと票が割れて決まりにくい |
| 2026-11-20 | どの案も承認ルールを満たさなければ、未承認者に「何が変われば承認できるか」を聞いて3案を出し直す（1回まで）。それでもダメなら承認数が最多の案に決定 | 元祖の「決まらないループ」を断つ |
| 2026-11-20 | 最多票が同数のときは、ホストが手動で決めるかルーレットにするかを選ぶ | 機械的に決めきれないケースの逃げ道 |
| 2026-11-20 | 代理人どうしの会議はなくす。AI の役割は「入力の補助（案を同じ型に整える）」と「○△✕ の判定」だけ | 元祖の不平等は AI の呼び出し元・キー・モデルが人ごとに違うことと、進行役の端末依存から来ている。判断は人間に戻す |
| 2026-11-20 | AI はすべてサーバー側で、固定モデル・同じプロンプトで動かす。個人の API キーやモデル選択は受け付けず、使ったモデルを画面に表示 | 参加者のクレジットやプランに左右されない平等さ |
| 2026-11-20 | v1 は Web（Next.js + Supabase）で作る。Discord 連携は後回し | まず流れを検証する |
| 2026-11-20 | 進行は締切ベース。アクセス時にサーバーが締切を判定して状態を進める（進行役の端末に依存しない） | 元祖の「代表者がページを開いている間しか進まない」問題の解消 |
| 2026-11-20 | v1 の既定：締切までに承認を送らなかった人は棄権として母数から外す | 未反応の人で止まらないようにする（元祖の弱点）。要検討 |
| 2026-11-20 | v1 の既定：誰の案かは決定まで伏せる（自分の案だけ「あなたの案」と表示）。譲れない条件は名前つきで見せる | 声の大きさ・遠慮の影響を減らす。条件は誰が何に引っかかっているかを見えるようにするため |
| 2026-11-20 | v1 では ○△✕ の手直し、合体案・AIの新案、AI 停止時の手動判定は入れない | まず流れを検証してから |
| 2026-11-20 | DB／バックエンドを Supabase から Convex に移す（移行はこれから） | 理由は [db-choice.md](db-choice.md)。自前で書いた「アクセス時に状態を進める」「ロック」「3秒ごとの問い合わせ」をサービスの機能に置き換えられる |
| 2026-11-20 | サービス名を **Temora（テモラ）** にする | 「Theme（テーマ）」＋「Aura（雰囲気・広がり）」の造語。短く覚えやすく、ハッカソン以外（勉強会・イベントなど）にも広げられる |
| 2026-11-21 | Convex への移行を実施。Supabase のコード・スキーマ・API ルートは削除し、画面は Convex のリアルタイム購読に変えた | 締切は scheduler（`runAt`）、二重遷移は mutation のトランザクション、AI は action で実行。自前のロックと3秒ごとの問い合わせが不要になった |
