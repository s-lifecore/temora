# Temora（テモラ）

参加者がアイデアや意見を持ち寄り、みんなでテーマを決めていくサービス。

**名前の由来**：「Theme（テーマ）」と「Aura（雰囲気・広がり）」を組み合わせた造語。短く覚えやすく、ハッカソンに限らず勉強会やイベントなど、幅広い用途に展開できる名前にした。

[MeetForMe](https://github.com/TAK0-wasa/ShipLab-Hackathon-2026)（ShipLab Hackathon 2026）が解こうとした「集まれないチームが、案を1つに決められない」課題を、別のアプローチで解き直すプロジェクト。

> ShipLab-Hackathon-2026（MeetForMe）の管理者の許可を得たうえで、その課題設定をもとに個人的なアレンジを加えて開発しています。

## 元祖との違い

|                | MeetForMe                                 | Temora                                                                                           |
| -------------- | ----------------------------------------- | ------------------------------------------------------------------------------------------------ |
| AI の役割      | 1人1体の代理人が会議して、推薦案を1つ出す | 全案を判断軸ごとに ○△✕ で照らすだけ。推薦しない                                                  |
| 決め方         | 推薦案を全員が承認                        | 候補（最大3案）に各自が承認を付ける。5人未満は全員、5人以上は3分の2以上で決定                    |
| 決まらないとき | 議論のやり直しを繰り返す                  | 1回だけ意見を集めて改訂 → それでもダメなら最多票。同数ならルーレットかホスト（会議作成時に選ぶ） |
| AI の平等さ    | 端末ごとにキー・モデルが違いうる          | サーバーで固定モデル・同じ指示・全案を1回で判定                                                  |
| 進行           | 代表者の画面が開いている間だけ            | 締切ベース。誰かがアクセスした時にサーバーが進める                                               |

## 流れ

1. ホストが会議を作る（お題・チーム共通の判断軸・締切・同数時の決め方・ページのデザイン）
2. 各自が案と「譲れない条件」（最大2つ）を出す。AI で案を同じ型にそろえられる
3. 全員提出 or 締切で、AI が全案を全軸に ○△✕ で照合
4. 譲れない条件で ✕ の案を外し、○ の多い順に最大3案を候補にする（ルール計算）
5. 各自が「これならいい」案に承認 → 決定

## 技術構成

- Next.js（App Router）/ TypeScript / Tailwind CSS
- Claude API（標準は `claude-haiku-5-5`。全会議で同じモデルを、サーバー側だけで実行。`AI_MODEL` で変更可）
- バックエンド：Convex（v1 は Supabase で作り、Convex に移行した）。理由は [docs/db-choice.md](docs/db-choice.md)

## 開発

```bash
npm install
cp .env.example .env.local   # 値は次の npx convex dev が自動で書き込む
npm run dev:convex           # Convex にログインしてデプロイ先を選ぶ。関数を監視して自動で反映する
npm run dev                  # 別のターミナルで
```

| コマンド                          | 内容                                                                                                                                               |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `npm run check`                   | 型チェック → lint → フォーマット確認 → テストをまとめて実行（コミット前に）                                                                        |
| `npm run typecheck`               | 画面側と Convex 側の両方を `tsc --noEmit`                                                                                                          |
| `npm run lint` / `lint:fix`       | ESLint（警告も失敗扱い） / 自動修正                                                                                                                |
| `npm run format` / `format:check` | Prettier で整形 / 整形済みか確認                                                                                                                   |
| `npm test`                        | ルール部分のユニットテスト（Vitest）                                                                                                               |
| `npm run build`                   | Next.js の本番ビルド                                                                                                                               |
| `npm run build:deploy`            | Convex を本番にデプロイしてから Next.js をビルド（Vercel などのビルドコマンド用）                                                                  |
| `npx convex run aiEval:compare`   | 判定の質と費用をモデルごとに比べる（`{"models":["claude-opus-5-5","claude-haiku-5-5"],"runs":2}` のように指定）。本物の API を呼ぶので費用がかかる |
| `npm run smoke -- 4 split`        | 一連の流れを関数呼び出しで通す（`.env.local` の接続先を使う）                                                                                      |

GitHub Actions（`.github/workflows/ci.yml`）で、push と PR のたびに check とビルドを実行する。

## 環境変数

`.env.local`（ローカル）と Vercel には、Convex の接続先に関わるものだけを置く。AI のキーや上限など、サーバー側だけで使う値は Convex の環境変数（`npx convex env set`、本番は `--prod`）に置く。`AI_MOCK` などは Vercel には書かない。

### Vercel

| 変数                      | 内容                                                                                                 |
| ------------------------- | ---------------------------------------------------------------------------------------------------- |
| `NEXT_PUBLIC_SUPPORT_URL` | （任意）応援ボタンの受け先（https のみ）。未設定なら応援ボタンは表示しない                           |
| `CONVEX_DEPLOY_KEY`       | Convex の本番デプロイキー。ビルドコマンドを `npm run build:deploy` にすると、接続先 URL は自動で渡る |

### Convex

| 変数                        | 必須 | 内容                                                                                                           |
| --------------------------- | ---- | -------------------------------------------------------------------------------------------------------------- |
| `ANTHROPIC_API_KEY`         | ○    | Claude API のキー                                                                                              |
| `AUTH_GOOGLE_CLIENT_ID`     | ○    | Google ログインの OAuth クライアント ID                                                                        |
| `AUTH_GOOGLE_CLIENT_SECRET` | ○    | 同じくクライアントシークレット                                                                                 |
| `AUTH_ALLOWED_ORIGINS`      | 本番 | ログイン後に戻ってよいサイトの URL（カンマ区切り、例 `https://temora.example.com`）。未設定なら localhost のみ |
| `AI_MODEL`                  |      | 使うモデル（未設定なら `claude-haiku-5-5`）                                                                    |
| `AI_DAILY_LIMIT`            |      | サイト全体の1日あたりの AI 呼び出し上限（未設定なら 300）。超えるとホストの手動判定に切り替わる                |
| `AI_MOCK`                   |      | `1` のときだけ AI を呼ばず見本の判定で動く。本番では設定しない                                                 |

### Google ログインの準備

1. Google Cloud Console で OAuth クライアント（ウェブアプリケーション）を作る
2. 承認済みのリダイレクト URI に `https://<デプロイ名>.convex.site/oauth/google/callback` を登録する（dev と本番で別々に）
3. クライアント ID とシークレットを Convex の `AUTH_GOOGLE_CLIENT_ID` / `AUTH_GOOGLE_CLIENT_SECRET` に入れる

## プランと上限

上限は `src/lib/plans.ts` のプラン表で決まる。今は無料プランだけで運用する。会議には作った人のプランが記録され、会議の中の上限（メンバー数など）はそのプランで決まる。

| 無料プラン                       |      |
| -------------------------------- | ---- |
| 1アカウントが1日に作れる会議     | 5    |
| 1会議のメンバー                  | 12人 |
| 1人あたりの案                    | 5つ  |
| 1人あたりの「AI で型にそろえる」 | 10回 |

サイト全体の AI 上限（`AI_DAILY_LIMIT`）はプランとは別の安全装置。

## コードの場所

| 場所                                 | 内容                                                                                                              |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| `src/lib/plans.ts`                   | プランごとの上限（今は無料プランのみ）                                                                            |
| `convex/auth.ts` / `convex/users.ts` | Google ログイン（Convex Auth）。会議を作るホストだけログインが必要                                                |
| `src/lib/designs.ts`                 | ページのデザイン（シンプル・楽しい・落ち着いた・クール）の一覧。見た目は `src/app/globals.css` の `[data-design]` |
| `src/lib/rules.ts`                   | ルール（必要な承認数・3案への絞り込み・決定）。純粋関数でテストつき                                               |
| `convex/schema.ts`                   | テーブル定義                                                                                                      |
| `convex/rooms.ts`                    | 画面から呼ぶ関数（作成・参加・案・承認・ホスト操作・表示用データ）                                                |
| `convex/model.ts`                    | 状態遷移と締切の予約                                                                                              |
| `convex/engine.ts`                   | 締切で動く関数、AI の結果の書き込み                                                                               |
| `convex/ai.ts`                       | Claude の呼び出し（Node ランタイム）                                                                              |
| `docs/`                              | 課題整理・決定ログ・DB 選定の理由                                                                                 |
